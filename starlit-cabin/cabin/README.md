# 星灯小屋

> 2026-10-03：默认生成器已切换为 DeepSeek。请优先阅读项目根目录 README，配置 `DEEPSEEK_API_KEY`。下文 Codex 说明适用于 `-Generator codex` 可选兼容模式。

本机塔罗页面：Three.js 小屋 + Python API + 现有 RAG 知识库。

## 启动

在 PowerShell 中运行：

```powershell
& 'D:\塔罗\塔罗\cabin\启动小屋.ps1'
```

打开 http://127.0.0.1:8787 。终端保持运行；按 Ctrl+C 停止。2026-10-02 用户已明确授权：默认启动 Codex 综合解读，将问题、实际牌阵和最多 6 段对应原书片段（每段最多 1500 字）发送到已登录的 Codex 模型服务。不发送整书或浏览器保存的称呼。已下载 Three.js，浏览器运行不依赖 CDN。

如只想使用本地原书解读、不调用外部模型，可运行：

```powershell
& 'D:\塔罗\塔罗\cabin\启动小屋.ps1' -Generator evidence
```

综合生成需要可用且已登录的 `codex` 命令。失败、超时、引用无效时，自动显示原书摘录并说明状态，不伪装为模型生成成功。

## 小屋功能

| 物件 | 功能 |
| --- | --- |
| 水晶球 | 镜头靠近，下方出现问题与牌阵选择 |
| 桌上牌堆 | 快速推镜、78 张牌从桌面展开；揭牌和解读持续对准桌面 |
| 藏书架 | 通过已有混合检索、重排查阅牌义 |
| 旧手记 | 在本浏览器回看最近 30 次牌局，刷新后可继续 |
| 烛台 | 开关原创舒缓钢琴纯音乐，默认静音 |

首次进入询问称呼，仅保存到浏览器。水晶球与牌堆按步骤发出微光；保留下方小功能栏，移除右侧面板。桌面展示 13×6 张牌，手机展示 8×10 个位置（末行 6 张），均为完整 78 张。减少动态效果设置会跳过快速推镜和散牌动画。

音乐为本项目原创的约 87 秒钢琴小品，包含旋律、分解和弦、低音及轻混响，文件 `web/assets/moonlit-piano.wav`，制作源文件 `compose_music.py`。

## 数据与安全边界

- 卡面来自用户提供的 PDF；提取时按各牌章节首页匹配。牌义保留原书 PDF 页码。
- 开局用操作系统随机源打乱 78 张牌，正逆位分别随机；服务端事务防止重复抽牌。抽完后浏览器校验承诺哈希和每次选择对应的牌。此方法证明牌序与承诺一致，不证明随机源无偏。
- 模型不能修改抽牌结果。先混合检索，再按实际牌名和正逆位筛选；不足时从相同元数据章节取证。
- 输入与输出有基础风险过滤。卡片摘要省略涉及医疗判断的句子；展开出处仍能查阅原书原文，原文观点不构成现实建议。
- 仅监听 `127.0.0.1`；校验本机 Host、同源 JSON 写入、正文大小和静态路径。不向浏览器暴露整部知识库或 SQLite 文件。
- `state.sqlite3` 保存问题、牌序、抽牌结果和解读。浏览器只保存访问令牌及记录入口；清空手记入口不删除服务器数据。令牌视为私密链接，不要分享。关闭服务后删除该数据库可重置所有本机牌局。
- 当前是单机开发版，关键词过滤有遗漏和误判的可能。公开部署需另做登录、HTTPS、限流、服务型模型接口、数据保留及删除功能、专业内容审核；不能直接将当前端口映射到公网。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 知识库、牌数、生成模式 |
| GET | `/api/cards` | 卡牌目录 |
| POST | `/api/sessions` | `{question, spread: "single" 或 "three"}` |
| GET | `/api/sessions/{token}` | 恢复本局与查询解读进度 |
| POST | `/api/sessions/{token}/draw` | `{index: 0..77}`，按所选牌背取牌 |
| POST | `/api/sessions/{token}/interpret` | `{}`，异步解读 |
| GET | `/api/knowledge?q=...` | RAG 牌义检索 |

## 验证与依赖

Python 3.10+、NumPy；卡面重新提取另需 pypdf（已提取，无需每次运行）。前端使用固定 Three.js 0.180.0，许可证在 `web/vendor/LICENSE.three`。

`test_cabin.py` 验证 API、并发重复选择、洗牌承诺、全部 156 种牌/正逆位证据、输入过滤、路径保护及完整原文解读。`browser_check.cjs` 使用本机 Playwright/Edge 验证桌面三张牌流程、书架、手记、声音与移动布局，包含环境专用的运行时路径。

实施顺序见 `实施规划.md`。前端素材不是占卜结果；结果始终来自后端随机牌局。
